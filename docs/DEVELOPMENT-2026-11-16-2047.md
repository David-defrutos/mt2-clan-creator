# Development

## Setup

Use Node 24 and npm for source development. Run `npm ci`, then `npm run build` and `npm start`. The creator uses localhost port 4320; its launcher tries the next available ports if needed. `npm run dev:server` starts the watched backend and `npm run dev:web` starts Vite on port 5174.

The source checkout intentionally excludes extracted official game resources and bundled third-party binaries. Download and extract the Windows ZIP from [v0.1.0-beta.5](https://github.com/David-defrutos/mt2-clan-creator/releases/tag/v0.1.0-beta.5). Copy `ClanCreator/catalog/official` to `catalog/official` in the checkout before running the build and tests. Use the Node runtime for your operating system. Legacy maintainer scripts that use `vendor/modding` require a separately prepared local directory.

The CI workflow is configured for Windows, Linux and macOS. Its resource step still points to the retired beta 4 ZIP. For local validation use the beta 5 catalog and run the commands below.

## Application versions

Set the version in `package.json` and keep the root package lock metadata in sync. The main screen and portable package read that version. Publish the ZIP from the same build with the matching GitHub release tag (for example, `v0.1.0-beta.5`). The portable ZIP's filename also carries the version.

The main screen checks public GitHub releases only when the user clicks **Check for updates**. Beta builds see prereleases, and stable builds follow stable releases.

## Structure

- **src/web/creator**: React wizard, examples, editing, previews and read-only JSON viewer.
- **src/server/creator**: drafts, native data copying, validation, generation and local installation.
- **config/creator.json**: wizard steps, recipes, abilities, localized text and validation settings.
- **config/official-clans.json** and **config/official-statistics.json**: included official references.
- **catalog**: audited examples, artwork and resource notices. Official resources are distributed in the release.
- **tests**: automated behavior, generation, installation and UI markup checks.
- **scripts**: catalog import, native status extraction, verification and distribution tooling.

The build generates the catalog search index for official and community examples in `dist-server/catalog-search.json`. Rebuild after refreshing examples or mechanic labels to update what the picker can find. Packaging regenerates the index after sanitizing the staged assets.

Import scripts may require local game data, decompilation or extraction tools. These are needed to refresh the catalog, not to run the creator. Consult each script's inputs before running it; personal workspace paths in import settings must be adapted to your own sources.

## Validation

Run `npm run build`, `npm run check:i18n` and `npm test`. The optional real compilation integration test requires the local game, SDK and either network access or verified compiler references in the local cache; enable it with environment variable **CLAN_CREATOR_TEST_COMPILE=1**, with the game closed. Other installation tests use isolated test profiles. Never point fixtures at an active player profile.

Tests verify native data preservation and generation; they do not replace testing cards in-game. Complex effects use native example copying rather than a standalone form for every engine class.

## Portable package

Run `npm run package:creator` on the target OS after preparing the catalog resources. The output is under **data/releases** and includes the host Node runtime, production dependencies, catalog, application and notices. Do not commit ZIP files or third-party binaries.

Before release, extract the actual ZIP into a new path, check file hashes, run start-clan-creator.cmd with a PATH that cannot resolve system Node, and verify the page, catalog and image processing. **scripts/verify-windows-distribution.mjs** verifies the extracted root recorded in **data/acceptance/windows-zip-current.json**.

Compilation downloads the exact releases and verifies each assembly using **config/compiler-references.json**. Trainworks Reloaded and Conductor come from their official GitHub release ZIPs. BepInEx BaseLib comes from the public BepInEx NuGet feed. When updating a dependency, update its release URL and verify the new assembly hashes before changing the supported version. The cache stays under **data/compiler-references**. In Install and play, the creator checks public GitHub release metadata in the background. Choosing a newer release verifies the archive against GitHub’s SHA-256 digest and updates the selected build references. Switching back preserves both caches. The selection does not alter the mod dependencies installed in the game. The creator ZIP excludes all of these assemblies.

A release should attach the tested ZIP and its SHA-256 checksum. Do not include development data, drafts, runtime configuration, workspace reports or personal profile contents.

## Guided workflow and portable drafts

Quick-start settings, step order, backup limits and bilingual UI copy are under **config/creator.json**. Quick mode keeps the existing draft schema compatible and prepares native official paths; it does not introduce a separate export format. Preview path/level selections are local UI state and never change saved cards.

Portable **.mt2draft** files include the validated draft and only referenced uploaded PNGs with hashes. Restore validates the complete payload before creating a new project identity; it never overwrites existing projects or installs anything. Built-in artwork remains referenced from the included catalog. Back up each draft before moving between portable distributions.

## Review, installation receipts and artwork

Review issues carry a card UID and field key for focused navigation. The wizard derives readiness from validation issues. Installation receipts use a canonical playable-content hash that excludes navigation and legacy review metadata. The per-project local-state.json stores destination, restoration date and last installation; it is excluded from portable backups. This records creator actions, not an automatic scan of the game profile.

Error guidance, effect groups and artwork defaults are configurable in config/creator.json. Search always includes uncommon recipes. Artwork uses shared preview/server framing geometry; source cropping precedes resizing to bound processing for extreme aspect ratios. Character imports preserve the original dimensions and transparency.

## Editing context, shared validation and public artwork

The local-state endpoint stores a validated editing view separately from playable content and portable backups. A removed card reference falls back to its containing step. Shared synchronous draftIssues checks drive inline messages, step indicators and installation readiness. The path comparison uses effectiveUnitStats for native upgrade bonuses, just like the card preview.

Collection filters sort copies of the card list and never reorder the saved draft. Replacement modes preserve the destination UID and reward settings; identity mode preserves name and artwork, and effects-only mode preserves base statistics. Native effect conditions are displayed as fixed values when editing them would require reinterpreting the original game behavior.

Expansion ownership is an explicit browser preference, without probing the game installation. Requirements are collected from example IDs used by cards, appearances and champion path levels.

scripts/distribution-art.mjs sanitizes a staging copy before packaging. Official combat character images from the base game and DLC are excluded. Their local image references are cleared and affected example hashes are rebuilt. Community character assets stay in the package. Card illustrations and themed frames are allowed. Card graphs, abilities and the full local catalog are preserved. Tests must accept DLC examples without local combat image previews.

## Guided card creation, recovery and collection backups

The configurable card wizard commits a new card only at its final step. Back retains its working values; Save and close preserves the pending card, and Discard explicitly removes it with an undo option. Existing-card editing keeps the complete form. Numeric controls validate before invoking changes and announce both the constraint and any retained previous value.

Validated per-step collection filters, sort order, paging, compact view and scroll positions are stored in local-state.json, excluded from playable hashes and portable draft backups. Statistics, overview and the main wizard are mutually exclusive views.

Recovery points live in each project's history folder. Configuration controls retention (20), automatic interval (two minutes) and maximum snapshot size. Manual points and pre-restoration points bypass the interval. Recovery validates schema, identity, revision and uploaded image paths; it preserves the current content first and never changes installed files. These points depend on the local project and are not portable backups.

Collection backups use the versioned mt2-clan-collection envelope with existing hashed .mt2draft entries. All entries are validated before writing any project, even when only some are selected. Restoration creates fresh identities; a failure rolls back only copies created by that operation. Limits default to 50 drafts and 128 MiB. Local installation receipts and recovery history are excluded.

Balance thresholds, minimum sample size, bilingual copy and wizard stages live in config/creator.json. Suggestions compare named reward cards with official references, exclude auxiliary cards and never enter installation validation. The overview uses existing card previews and links to existing editing steps.

## Art workshop and additional clan resources

config/creator.json defines aiArt resources, bilingual requests, format sizes and prompts. Draft.artDesign holds the shared style, palette, exclusions and optional reference asset. Draft.artwork holds resource briefs, applied images, source images and request text. These optional fields preserve compatibility with existing drafts. Metadata alone does not change the installation hash; additional applied resource images do. Recovery and portable backups include all referenced uploads, including source sheets and the style reference.

Grid presets use normalized source rectangles; users can adjust bounds when generated cells are irregular. Preview and Sharp share sourceCropPixels. The selected region is cropped before resizing, and a normalized full-resolution source is retained when preserveSource is requested. Character imports preserve the selected silhouette's dimensions. The workshop uses 210×250 illustrations without changing the older 512×512 image import path. Frame sizes match the included Hellhorned templates: unit 495×588, spell 499×515, equipment/room 495×480; update those configured dimensions when changing templates.

applyClanArtwork adds independent sprite references for custom frames, banner states, map/minimap icons and champion presentation. Room/equipment frames remain independently assignable even when defaults share a sprite. Draft source sheets, reference images and prompt text are not copied into playable output unless that image itself is deliberately assigned as artwork. Generation does not invoke an AI API or send local resources to external services.

## Guided art workflow and unfinished cards

The workshop renders one of four screens at a time. ArtLibrary filters localized target labels by category and shows custom, included-example, game-resource, placeholder or unavailable states. Original game character references never use a card illustration as a fake combat preview. Art sizes explain prepared outputs separately from preserved character resolution; prompt generation uses formatCharacter for the latter.

Starting styles, category order, history retention and playtest checklist definitions live in config/creator.json. The art-variants endpoint validates ownership of the source reference within the saved draft, reads bounded images and returns previews without mutating the draft. Logo size variants, white alpha silhouettes and champion portrait/icon variants are local image operations, not AI generations. Persist current artwork before requesting variants. An opaque source yields a warning and no fabricated silhouette.

Artwork comparison stages uploaded proposals until acceptance. ArtRecord.previous stores at most five previous image/source/prompt/placement versions. Restore changes only the selected resource. All referenced historical uploads are included in portable backups; byte limits still apply. Empty metadata and previous versions do not affect installation hashes.

Draft.pendingCard contains the provisional card and wizard stage. It is validated separately, survives portable backups and recovery, and is excluded from playableContent and allCards. Early unfinished equipment may lack its example. Completion atomically clears pendingCard and appends its existing UID to finished cards. Pausing flushes the latest working values before persisting. Returning to a draft opens its pending card; the main wizard also offers an explicit resume action.

Manual playtest checks live in local-state.json, bound to the canonical playable-content hash. The server accepts them only for the current installed version and rejects unknown check IDs. They are excluded from portable backups and cannot be inferred from successful compilation or installation. The UI omits the spell test when the clan has no spells, and disables checks for pending or removed installations.

## Official clan classification

Missing card class fields mean Clanless, never Railforged. Relics use extensions.collectable.class. The importer uses officialClanForRoot. config/official-clan-overrides.json corrects historical catalog metadata at runtime, including the release fixture, without rewriting audited example bytes or hashes. Clanless appears as a card group in example filters; it is excluded from full-clan templates, which require two champions and their paths. DLC requirements remain independent of clan membership.
